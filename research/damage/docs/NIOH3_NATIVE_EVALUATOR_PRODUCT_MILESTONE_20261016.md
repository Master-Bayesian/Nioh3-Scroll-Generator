## Product boundary

Use explicit semantic inputs, with current IR records and fingerprints retained:

- CharacterProfile: levels/attributes plus authenticated nongear source history;
  do not reuse a gear-contaminated late source as a pristine initial value.
- Loadout: actual item instances, slots, legal discrete fields, sets and the
  weapon/record actually used by each scenario's action.
- Scenario: enemy/action/reference/weights and state policy. Candidate-dependent
  HP, effects, attack records and packet fields are rebuilt. A fullHP policy
  means each candidate's currentHP equals its own maximumHP.
- RuleCatalog: executable typed operations, applicability, source order, rounding,
  thresholds, caps, state transitions, version and evidence. Coverage metadata
  alone cannot authorize numerical execution.

`evaluate(profile, loadout, scenarios, rules)` returns per-scenario damage and
same-candidate HP/currentHP/agility/toughness, hard-constraint witnesses/margins,
coverage and calculation trace. Any relevant unknown blocks unsupported claims
before search; it never becomes zero damage or an infeasibility certificate.

Retain ordered f32 operations, source/active-weapon selectors, set thresholds,
discrete choices, conditional/temporal rules and native dependencies. Aggregate
compression and query folding are allowed only with established semantics for
the declared query/candidate domain. A baseline-only observed branch cannot
eliminate paths that a different candidate may activate.

## Search and performance

For fixed positive reference denominator, a weighted damage ratio can search the
weighted numerator and format the ratio afterward. Single-hit, fixed-combo and
timed output are different objectives. Speed/resource/cooldown/uptime effects
need explicit sequence/state-transition models for timed objectives; all-effect
support does not mean every effect multiplies single-hit damage.

Pause additional PG/Gumbel/GPU investment until real workloads justify it. Keep
the existing baselines. Set-aware LNS is a candidate to benchmark after native
scoring works, not a preselected algorithm winner or a fixed2-4slot restriction.
Permit set thresholds, compensating HP/weight/toughness changes and instance swaps.

Keep exact candidate evaluation distinct from conservative branch bounds. The
current integer synthetic bound cannot certify real binary32 rules. Without a
proved bound, return a best found feasible candidate without a fabricated gap.
Gradient-guided search remains eligible; gradient/tangent pruning needs its own
valid global bound and linear-oracle guarantee. All unprocessed regions, including
an interrupted partial expansion, must remain in certificate accounting.

No new algorithm implementation, production model switch, release or full-formula
acceptance is claimed by this decision. The next Pro package must use these
product acceptance criteria as its main task and include the fresh evidence as
supporting calibration material.
