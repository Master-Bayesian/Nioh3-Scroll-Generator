## Position

An Astra-led incremental Rust backend migration is active under the project
owner's direction. The first slices are standalone domain/data libraries with an
offline cross-language parity gate; M1 enemy-generation parity is verified locally.
The shipped React/WebView2 product and its
one-file delivery contract are preserved while backend components are replaced
incrementally, and the production backend has not switched.

M2.1 adds the ordinary NG3 effect-sequence path to those offline libraries:
effect tables, scroll records and the sequence core, parity-gated against the
retained Python reference through the production data adapter (549 emitted rows
with zero differences, including a 216-row cross-level sweep that exercises the
curve clamp, three native byte anchors, and a permanent adapter content-parity
guard). M2.2 adds R4 completion finalization and the paired stage-one/install and
finalized/preview records, byte-exact against all ten tracked 232-byte native
pairs through the same production adapter, with a measured reveal-branch
comparison and a corrected effect-area level-sensitivity measurement. M2.3a adds
a development-only Rust read-only worker that serves the preview subset over the
shipped framed-JSON protocol, matching the Python worker on a 189-preview
subprocess matrix and passing runtime independence checks (it answers with
Python absent from `PATH`, fails closed on an empty data root, and rebuilds from
the current candidate). All three are local offline evidence only.
`GenerationContext` digest binding over the wire, candidate identity beyond the
preview payload, search orchestration, product wiring and packaging remain
unimplemented, and the native corpus exercises only `reveal = true` at level 180.

M2.3b1 serves a bounded search surface inside the development worker and its
acceptance is green: the preview gate derives the contract's method set from
`request.schema.json`, validates every frame against `response.schema.json` and
compares the whole `capabilities` object against live probes, and the search gate
covers the canonical v0.7.5 three-rule regression in one continuing job with its
bounded control, effect/enemy page identity/order/cursor parity, auxiliary-only
pages at rarity 3 and 5, responsive cancel and resume, resume-token rejection
(forged, changed query, context, policy, continuation and cross-process),
candidate ownership and export, accelerator absence, and the unported NG4/NG5
boundary. Measured on the frozen tree: `tests/migration` 78 passed / 0 failed,
`cargo test` worker 66 library + 3 binary / domain 71 / data 17, all zero
failures. The served routes are the fused auxiliary pivot and the rarity-4
primary pivot; effect-preimage searches, rarity-3 primary search,
secondary/roll-only replay, Grace-filtered pivots, terrain option ids and
playthrough 4/5 are refused with a reason naming the missing route, and the
DirectCompute effect filter and NG4/NG5 cache are not advertised. No product
cutover, package, tag or publication is implied, and nothing is wired into the
shipped host.

### Direct-save install lifecycle state (2026-09-20)

(`+0x18`..`+0x1B`) as the game's own insertion result, `0x06800082`, instead of
inheriting the donor template's flags. The value is the builder descriptor state
`0x02800002` plus the engine insertion bits `0x04000080`, taken from retained
captures (the DLC pickup chain and the accepted native live-add delta); the first

keeps the new-item marker. The change is confined to the installation boundary -

install) and `crates/nioh3-save/src/codec.rs` / `transform.rs` - so previews and
materialization, generated effect bytes, rarity/stage-one payloads,
editor/delete/restore and live addition are unchanged. Evidence:
`tests/test_post_insertion_state.py`, the `nioh3-save` unit tests, and
`tests/migration/test_save_batch_install_parity.py` (byte-identical Rust/Python
saves with the asserted word, R3/R4/R5).

## Implementation and release decisions

- The first slice adds Rust domain tests and cross-language parity to push/PR
  CI. Existing desktop tests already run in `frontend-v2.yml`; host/launcher
  Rust tests remain release gates until their next affected slice.
- Whether the C++/CUDA numerical helpers are ported, kept, or replaced, which
  needs its own parity and performance decision rather than language uniformity.
- The first product cutover targets read-only generation and preview after
  exact output and worker lifecycle parity. The primary agent defines each
  bounded assignment; later write-path acceptance follows its operation risks.
- The v0.8.0 version bump, tag, release notes, and publication window.
