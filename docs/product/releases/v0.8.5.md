# v0.8.5 engineering record

Status: **published 2026-10-04** (tag `v0.8.5`, commit `9e81a29`; [publication record](../../knowledge/TAURI_V085_PUBLICATION_20261004.md))

Base: `v0.8.4` publication record commit `2b9bed8`.

## User-visible changes

- Soul-core names (#32): all 84 real soul cores now carry the name the game
  shows, `{yokai}的魂核` (owner-confirmed against 一目连的魂核 in game). Six
  previously unnamed cores are now named and addable: 一目连 (36404), 铁鼠
  (49342), 垢尝 (56028), 雪入道 (25807), 蛤蟆附身 (20413) and 大蛤蟆 (12196).
  0x3336 (13110) is 狱卒鬼（业风）的魂核, not Sudama; Sudama is 48491.

- Save-file equipment edits after an in-game save (player report, v0.8.4):
  edits are planned against the save session snapshot digest, but Reload
  only re-read the character, so after the game wrote the save every add or
  edit failed with "Save changed since it was read" until the tool restarted.
  Loading the character now refreshes the snapshot first.
- Live remaining-count edits never ran in the Rust host: the host named a
  backup path but never wrote it (os error 3), and replies lacked the
  contract's `{count_edit}` wrapper (INVALID_RESULT). The host now takes the
  live-addition checkpoint (action `v2-count-edit`); live on PC v2.02 a scroll
  went 6 -> 5 -> 6, both verified.
- 服部半藏（前代） replaces the workbook label 先代／父（鬼半藏） (owner, from the
  in-game scroll view). Temporary overrides (#1) were accepted in game on
  v0.8.4: the replaced enemies and hell terrain showed on the scroll.
- Launcher failure dialog and recovery hints in Chinese (#31).
- CI: `verify-scroll-completion.mjs` replays its recorded replies from
  `test_fixtures/` instead of a host-local folder.
- Live scroll addition (single and cart batch) was re-accepted in game on
  v0.8.4 bytes.

## Soul-core evidence

The game builds the name at `Nioh3.exe+0x1F1730B` (PC v2.02): the item row's
`+0x180` u16 yokai key is looked up in the parameter manager
(`[Nioh3.exe+0x45B9E30]+0x118`: key map of u16 key / u32 index, rows of 0x54
bytes), and row `+0x10` is the yokai name text id, formatted with text
`0x010D29F1` (`{}的魂核`). Read live and read-only on 2026-10-04, the derivation
reproduced 77 of 78 curated names; the exception was 13110 above.
`test_fixtures/soul_core_yokai.json` keeps the result with
zh-CN/en-US/ja-JP yokai names (by text id from `auxiliary_names`). The other
55 soul-core rows are placeholders: key 0 (the builder has no name) or the
shared 饿鬼 key `0x46DA` on rows other than the real 饿鬼的魂核 (33859). They
stay unnamed and hidden. `apps/desktop/tests/item-names.test.ts` pins every
real core to the derived name.
