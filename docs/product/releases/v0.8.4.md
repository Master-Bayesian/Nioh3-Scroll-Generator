# v0.8.4 engineering record

Status: **release candidate; version 0.8.4 set, merged to `main` for the release workflow**

Base: `v0.8.3` publication record commit `a0623f1`.

## User-visible changes

- System save size (blocker carried from v0.8.3): the account system save is
  a transaction companion that is only fingerprinted, backed up and restored,
  never decoded, but its read was bounded at the old exact container size
  (235384 bytes). The 2026-09 game update writes 235896 bytes, so every
  save-file edit and install was refused. Its bound is now 1 MiB
  (`SYSTEM_COMPANION_MAX_BYTES`); main and game-backup saves keep their exact
  size. Verified on a sandbox copy of a real updated account: a gold edit
  planned, committed, backed up, and left the system save byte-identical.
- Live editing follow (regression from v0.8.3): the closed-menu reply of
  `runtime.menu_selection` carried a `diagnostics` object the protected
  contract did not list, so every poll with the inventory menu closed was
  refused as INVALID_RESULT. The contract lists it now; reproduced and
  re-verified read-only on PC v2.02, together with every other read-only
  runtime method. `tests/menu_selection_contract.rs` covers all menu states.
- Live equipment addition (never worked in game since v0.8.3; it had only
  synthetic-helper evidence). Three defects in the native dispatch:
  1. The idle predicate required RCX to be the scheduler and read the pickup
     queue on the scheduler; RCX is the pickup object, as the 2026-09-26 live
     insertion and the legacy transport check. No hit was ever idle.
  2. A target hit after an entry that was let through (not idle) was taken as
     the stub's acknowledgement and read an unwritten record ("preview changed
     inventory"). Only a redirected run can acknowledge now.
  3.  received the bare seed instead of the seed
     word (seed << 16 | 1), generating a different item; the preview check
     refused it.
  The synthetic helper modelled RCX as the scheduler, so its E2E passed. Live
  on PC v2.02 (owner-approved test save): seed 48129 of item 14145 previewed
  with exactly the predicted effects and inserted as the 1554th piece.
- Compatibility backups are pruned to the newest three after each verified
  copy; remembered consent (below) would otherwise copy every save per launch.
- Loadout codes (#16): `N3E1-` + base64url of varint fields per piece (item,
  level, forge level, plus, rarity, hell skill, effects with star) and a
  16-bit checksum. Copy one piece, the worn loadout or all favorites; pasting
  checks items and effects against the shipped tables and saves the pieces as
  favorites, which "Queue all" adds as 魔改 additions (save-file mode).
- Dark mode (#14): the build rewrites every declaration color to a token and
  derives a dark value by flipping OKLab lightness (hue and chroma kept);
  Settings -> Appearance offers System / Light / Dark. style.css is unchanged.
- About & safety (#15, #7): free-of-charge statement, official sources, what
  the tool reads, writes and connects to, and how to check an antivirus
  warning. No scan result is claimed. The announcement channel half of #7 is
  deferred to around 1.0 by the owner.

- Settings opens a small menu beside the sidebar button (display toggles,
  game version, feedback, updates). Game version details open as a second
  panel from the menu instead of filling the menu with diagnostics.
- Equipment & items: owned and add lists filter by class, then weapon type,
  armor slot or accessory kind, with a samurai/ninja choice for armor. Counts
  show on each chip. The save-file and live add catalogs share this grouping
  and sort by type, then name (issue #30, part 1; set browsing is deferred).
- Equipment, item and add lists scroll; the eight-row pager is gone.
- The selected row shows an "unapplied" badge while the editor has unapplied
  changes; the edit state and the paused-follow note are badges (#17, #18).
- The save picker is one line on every page; the equipment page shows one
  reload button.
- Favorites is a sidebar page (#20).
- Equipment sets (#30): a 套装 filter groups set pieces across weapons, armor
  and accessories by their set effect (56 sets, 343 pieces from the v2.02
  item table's set-effect id, generated by `item_sets`).
- Equipment favorites (#21): the star next to an owned item's name saves it;
  saved pieces load into Add new equipment -> 收藏 for any character.
- The backups page is 存档管理 / Saves and adds save re-sign (#6): pick another
  SAVEDATA.BIN, and it replaces the selected slot re-signed to that account
  (header Steam id and own scrolls; shared scrolls keep their owner), with the
  usual backup first. In-game load of a re-signed save is not yet accepted.
- The game compatibility notice has "don't show again for this game
  version". With it, later requests back up and enter compatibility mode
  automatically; a block, failed backup or game update shows the notice again.
- Live equipment addition backs up the save chosen in the shared save picker
  instead of asking for a typed SAVEDATA.BIN path.
- Item names show their exact translation or the Chinese name, never a
  piecewise substring translation.
- Backups show readable local times, newest first, with backup actions ahead
  of folder actions. The save worker now reports the backup directory's
  modification time (Unix milliseconds) in `timestamp`.

## Preserved

Save, backup, confirmation, recovery, live-add ownership and generation
behavior are unchanged. The protected contract adds `save.prepare_resign` and the `resign` plan kind.
