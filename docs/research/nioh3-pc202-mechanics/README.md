# 仁王 3 · PC v2.02 伤害机制手册

**多才多艺和架式增伤分属两个结算阶段。** 对进入对应分支的命中，多才多艺先和普通「造成伤害增加」进入早期伤害池；上、中、下段的装备词条在后面的装备池结算。素盏七件改的是多才多艺自身的倍率。琢技又有自己的发动条件，主增量送入后面的池。只看装备文字上的「伤害增加」，很容易把这三件事算到一起。

- [六种伤害反映、属性加点、敏捷与持续武技](./CURVES.md)
- [优化器状态图、证据索引与离线复核](./PROTOCOLS.md)

版本以 PC 可执行文件的 **2.0.2.0** 为准。文中「表值」表示从该版资源读取，「指令」表示核对了原始指令中的读写与运算，「回放」表示用保留输入重算，「游戏观测」表示已有玩家读数。训练武士、正面、一段命中等条件随例子给出。「待实证 / 暂未完全建模」指出具体缺失的环节。

## 一次命中怎样变成伤害

**第一步是重建这套装备的输入。** 优化器按候选角色的两套装备、当前流派和属性要求收集来源。先处理武器，再处理防具和饰品、绘卷、套装奖励及已绑定的角色来源，然后将结果写入角色数值表（STAT）与词条表（D）。同组装备词条按该组规则合并，有按值累加和封顶的组，也有保留最大值、另记重复次数的组。状态对象还要单独处理触发、竞争与生效顺序。[来源 1、2](./PROTOCOLS.md#sources)

**第二步是给每段命中单独取输入。** 所持武器的攻击记录、动作的物理与属性动作值、命中方向、目标防御、双方状态和命中包标记都可能改变分支。近战刀击、固有属性和另行生成的飞行道具可走不同路线。全中的多段武技逐段算，持续武技还要先确定本套装备能打到哪一段。[来源 1、3](./PROTOCOLS.md#sources)

**第三步是原生 MAIN。** 下面写的是已追踪的「刀・中段・第一下速攻击，训练武士」物理路线。它给出了可算的基准，其他动作沿各自的分支重算。[来源 3](./PROTOCOLS.md#sources)

```text
基础伤害 = (物理动作值 / 100) × 500 × 攻击曲线(命中包攻击力)
防御修正后的小计 = 基础伤害 + 攻防差修正
物理结果 = 截去小数(min(999999, 小计 × 参数因子 × 动作因子
                                   × 早期状态因子 × 后段装备因子 × 目标等因子))
```

该路线的动作值为 26。攻击曲线在相邻断点间线性插值，例如攻击 2300 对应 4.1，9300 对应 11.1。攻击超过防御时，正差按参数表的五档计算；低于防御的样本也有扣减。无甲样本的攻击 2632、防御 2636，基础伤害 576.16，修正 −4，装备因子约 1.2483，最终 **714**。另一套带绘卷的样本，攻击 2994，基础伤害 623.22，修正约 +210.26，装备因子约 1.3369，最终 **1114**。这两行仅在展示时四舍五入，回放按原始单精度运算顺序执行。[来源 3](./PROTOCOLS.md#sources)

**怎么判断加算或乘算？** 原生函数会为特定阶段、特定伤害分量维持一对数，初值均为 1。收到因子 `m ≥ 1` 时，增益端加 `m − 1`；收到 `m < 1` 时，减益端乘 `m`。这一对最终取乘积。多个阶段复用同一段函数代码；要看传入的是哪一对数。在上面的中段速攻样本，近距离、中段、速攻、装备重量反映、心／刚词条反映和无伤近战等正项，在后段池内相加。新增 10 个百分点，对已有 1.3369 的池只带来约 **7.48%** 的相对提升，取整还会影响跳字。[来源 3、4](./PROTOCOLS.md#sources)

**物理、属性和总伤害各留一份。** MAIN 保存本段物理和属性结算值，并在总值槽结算。多段评分按原顺序分别累加每段的总值、物理值和属性值，以保留单精度舍入。以大太刀速攻为例：已有原机回放得到物理 1394、水 317、总计 1711。带水武器打出的属性伤害与目标身上的水异常是两个独立输入。[来源 1、3](./PROTOCOLS.md#sources)

## 多才多艺、素盏七件与琢技

**PC v2.02 实机已验证 1–4 层状态，以及三层同招叠修罗符。** 16 帧均读到 `D+0xAAC ≈ 0.20`，第 1–4 层的对象倍率依次约为 **1.042、1.084、1.126、1.168**。同目标、同动作值、同攻击包的零层至三层伤害为 **987 → 1,333（1.3506×）**，吻合素盏七件对整个对象倍率的缩放 `1.126 × 1.20 = 1.3512`。三层叠修罗符实测 **1,853**，聚合 `+7C ≈ 1.5266`，吻合早期池加算 `1 + 0.3512 + 0.5266 = 1.8778`。若两项直接相乘，同一基准会给出 **2,035–2,037**。[16 帧抓包与数值对照](./PROTOCOLS.md#versatility-live)

### 手甲「连绵」（Unbroken）

**倍率在哪里加？** 手甲资源第 181–190 行的事件条件逐一匹配第 1–10 层。该组两个原始倍率字段都是 `100 + 5n`，按 `f32((100 + 5n) * f32(0.01))` 换算，对应约 **+5% 至 +50%**。原始指令显示，符合条件的事件可写动作状态 `state+0xE98/+0xE9C`，受事件标记和状态倍率修正等条件约束。MAIN 在 `0x78D88C–0x78D8E5` 读取这两项，将高于 1.0 的部分分别加进早期物理、属性伤害池。多才多艺和胜出的 `0x312` 状态也在这个池里贡献增量。[来源 4、5、15、16](./PROTOCOLS.md#sources)

**实机四层对零层。** 同一动作 `25035` 的两段分别对照。四层时唯一的活跃来源状态为 `0x19C`，两路动作倍率均为 `0x3F999999`（约 1.20）；零层时两路均为 1.00。四帧的命中包攻击值 `+0x08` 均为 **2821**，攻击方状态聚合区 `+0x38..+0x88` 的八个已读倍率均为 **1.0**。[四帧抓包，来源 15](./PROTOCOLS.md#sources)

| --- | ---: | ---: | ---: |
| 第 1 段（25／10） | 819 | 962 | 17.46% |
| 第 2 段（7／2） | 271 | 317 | 16.97% |

四层约 0.20 的增量是加到原有早期池上的。以零层池值 `P` 为基线，该池的相对增幅是 `0.20 / P`，因此同池已有增量会稀释最终涨幅。两段实测均低于 20%，最终跳字还会受取整影响。[动作倍率与实机结果，来源 15](./PROTOCOLS.md#sources)

**证据边界。** 实机捕获了 MAIN 读到的动作倍率，事件写入点未抓到。用中性初值执行原始 MAIN 倍率片段确认了入池方式。四帧从 MAIN 入口跑到结果的离线回放均在 `0x78C9A9` 因缺少查表输入中止，表中扣血来自实机。第 181–190 行这组与四层实机倍率位模式吻合，其他三组 `0x3B7–0x3C0` 事件的触发和用途尚未展开。同时叠加多才多艺等状态的整击仍待实测。[来源 15、16](./PROTOCOLS.md#sources)

| 多才多艺 | 对象倍率的正增量加进 MAIN 早期池。素盏七件先修正对象倍率，九层约为 `1.420 × 1.20 = 1.704`，入池约 +0.704。 |
| 刚力丹／修罗符 | 同属 `0x312`，组内胜出的倍率通过聚合区 `+0x7C` 进入 MAIN 早期池。 |
| 宿心升华符 | 实机中 `0x17D` 的 `1.4500000476837158` 与修罗符 `0x312` 的 `1.5269999504089355` 先相乘，写入 `+0x7C = 2.2141499519348145`（`0x400DB4A2`）。MAIN 将该聚合值超出 1.0 的部分加进早期增伤池。[六帧证据](./PROTOCOLS.md#soul-purge-live) |


### 套装怎样计件

| 问题 | 原生规则 |
| --- | --- |
| 两套流派各带一件，可以随意凑两件吗？ | 套装在各自装备表分开收集，再按奖励行的流派标记判定。实表套装 `41164` 的第 0 行奖励 `37872` 需两件、标记 2；两件都在备用流派也能向当前流派派发该行。此证据不能推广为主备两表件数任意相加。 |
| 八尺琼勾玉的「套装所需件数 −1」能叠两次吗？ | 检查对应收集表有没有组 `38BA`，按存在给 0 或 1。奖励判定使用该行指定的普通／特殊件数，再加这个 0 或 1 与门槛比较。重复来源不会把门槛再降一级；零数值的该组依然有效。跨流派奖励仍须按该行所属表核对减件资格。 |
| 相同物品的两件副本怎么算？ | 固定套装按指定的原生物品键占位置；同键副本可更新该位置的等级，不能新增一个位置。自由计件的恩宠有七个成员位置，合格装备按件填入。同一背包实体不能同时占两个装备槽；两个实际拥有的相同副本仍是两个实体。 |
| 第 15 槽的绘卷怎么算？ | 生效流派的绘卷结算平攻击、平防御并收集词条。攻击加值向六条记录的两个攻击字段各加一次。备用绘卷只处理代码列明的三个组；不能把两张绘卷平攻相加。若要认定某张绘卷提供套装件数，还需该记录的实际来源和收集规则。 |

实表的 `41164/37872` 是「套装键／奖励键」；减件组另为 `38BA`。套装达到门槛只说明有资格派发奖励，像多才多艺这样需要命中和活动对象的效果，仍须满足自己的触发条件。[来源 1、2、5](./PROTOCOLS.md#sources)
